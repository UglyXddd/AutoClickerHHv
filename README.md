# jobfinder v2.0 (разработка) — поиск работы на hh.ru

Небольшая программа на Python и Playwright. Открывает отдельное окно браузера,
даёт человеку войти на hh.ru, после Enter в терминале проверяет вход
и продолжает работу в том же окне, вкладке и сессии. Браузер остаётся видимым;
его можно свернуть и открыть с панели задач, чтобы проверить происходящее.
При CAPTCHA картинка приходит в Telegram, а ответ человека вводится в исходную
форму без перезапуска сессии. Проверку также можно пройти прямо в браузере:
программа обнаружит завершение и продолжит работу без ответа в Telegram.
Терминал остаётся для управления и сообщений.

По умолчанию программа работает постоянно. При запуске проверяет доступные резюме,
затем проверяет вакансии и отправляет подходящие
отклики с сопроводительными письмами. Когда текущая поисковая пачка обработана,
модель создаёт следующий запрос по резюме; обработка продолжается в том же цикле.
Например, после 40 вакансий первого поиска сразу начинается следующий поиск,
без ожидания конца четырёх часов. За цикл все поиски вместе проверяют до 400
вакансий и соблюдают общий `max_applications`. После границы цикла
лимиты обновляются, поиск продолжается до остановки пользователя
или исчерпания бюджета API.

Программа открывает полный список резюме, учитывает таймеры hh.ru и не меняет
видимость резюме. Ручное поднятие доступно раз в четыре часа:
[справка hh.ru](https://feedback.hh.ru/knowledge-base/article/0012145).

Поднятие работает по таймеру каждой карточки резюме, независимо от поискового
цикла. Например, если при запуске осталось 45 минут, следующая проверка назначается
через 45 минут. Программа читает «сегодня/завтра в ЧЧ:ММ» и относительные таймеры,
а в консоли показывает время следующей проверки по Москве. Когда резюме несколько,
первым проверяется ближайший таймер. После успешного поднятия читается новое время.

Во время ожидания между вакансиями, при пустых поисках и после исчерпания лимита
проверки поднятия продолжаются. Для них используется отдельная вкладка того же
браузера. Открытая форма отклика и её данные сохраняются. Начатая отправка,
CAPTCHA и запрос к модели завершаются прежде, чем начнётся плановая проверка.
На паузе `INeedSomeSleep` поднятие также приостановлено.

Кнопка проверяется заново на сайте: скрипт нажимает только доступное бесплатное
поднятие. Если формат времени не распознан или страница временно не загрузилась,
повторная проверка назначается через минуту. Скрытые резюме не раскрываются.

Другие режимы задаются параметром `--task`:

- `bump` — только поднятие всех доступных резюме.
- `search` — запрос и фильтры по резюме через OpenAI, затем сбор вакансий общего поиска hh.ru.
- `apply` — оценка соответствия вакансии, письмо через OpenAI и отклик.
  Вакансии с анкетой добавляются в избранное и журнал, без заполнения анкеты.
- `all` — сначала поднятие всех резюме, затем подбор и отклики; режим по умолчанию.

Основное резюме уже указано в `config.json`:
в моем случае:
`8b282e8cff0d8bdb180039ed1f413839487a4b` (Python Backend-Разработчик).
OpenAI Responses API: `gpt-6-luna`. Локальная модель больше не используется.
Архив исходной версии с Ollama сохранён отдельно в `../releases/jobfinder-v1.0.zip`.

## Ключ и расходы OpenAI

При первом запуске `start.cmd` вставьте API-ключ в терминал: ввод скрыт.
Он сохраняется в `.openai-api-key` рядом с `main.py` и исключён из Git.
Можно заранее записать ключ в этот файл или задать `OPENAI_API_KEY`.
Ключ не следует добавлять в `config.json`. В журнал он не выводится.

В `config.json`, блок `openai`:

- `model: "gpt-6-luna"` — экономичная модель; также предусмотрена `gpt-5.4-mini`.
- `budget_usd: 4.5` — суммарный локальный предел расходов проекта, включая предыдущие запуски.
- `max_output_tokens: 1600` — предел ответа, включая скрытые токены рассуждения.
- `reasoning_effort: "none"` — без дополнительных рассуждений для экономии.
- `timeout_seconds: 90` — время ожидания ответа.

Тариф GPT-6 Luna на 30.10.2026: $0,10 за миллион входных и $0,50 за миллион
выходных токенов, чтение кэша $0,01 и запись $0,125 за миллион.
Источники: [модель](https://developers.openai.com/api/docs/models/gpt-6-luna),
[Responses API](https://developers.openai.com/api/reference/resources/responses/methods/create).
Фактическая стоимость зависит от длины резюме, вакансий и ответов; число
вакансий на $5 заранее не гарантируется. Выбранная модель должна быть доступна ключу.

Программа показывает оценку стоимости каждого вызова и накопленный итог.
История расходов и кэш хранятся в `output/openai-usage.sqlite3` и сохраняются
после перезапуска. Не удаляйте этот файл, если хотите сохранить лимит и кэш.
Повтор одинаковой оценки вакансии берётся из локального кэша без обращения к API.
Для каждого нового поиска модель получает номер прохода и последние 20 запросов:
поисковый план не застревает на первом ответе из кэша. Повтор недавнего запроса,
включая перестановку слов, не принимается. История запросов и номера
проходов сохраняются в `output/state.sqlite3`, включая перезапуски.
Перед платным вызовом резервируется верхняя оценка его стоимости. Если ответ
потерян, резерв остаётся; автоматического платного повтора нет. Ошибка ключа,
лимита аккаунта или локального бюджета останавливает программу.

Это оценка расходов данного проекта по сохранённым тарифам, а не доступ к балансу
аккаунта: расходы друга и других программ не видны. Изменение тарифов также нужно
учесть отдельно. Удаление базы или изменение каталога `output_dir` начинает новый учёт.
Лимит $4,50 оставляет запас от заявленных $5.
В режиме `--dry-run` обращения к OpenAI тоже платные: отключаются действия на hh.ru,
а оценка вакансий и подготовка писем выполняются обычным образом.

В OpenAI передаются профессиональные разделы резюме, описание вакансии и правила
письма. Контакты специально не считываются. Запросы используют `store: false`;
это отключает сохранение Response для последующего получения, но не обещает
полного отсутствия служебного хранения у провайдера. Отправка данных нужна
для подбора поиска, оценки соответствия и составления письма.

Формат письма записан в `letter_style.txt`, можете прописать под себя и/или под свою модель:

1. «Здравствуйте!».
2. Основной подтверждённый стек.
3. Конкретный интерес к вакансии и подходящий опыт под требуемый стек.
4. «Буду рад обсудить детали.».

Модель получает профессиональные разделы выбранного резюме и описание вакансии.
Она возвращает оценку 0–100, обоснование, основной стек, абзац об интересе и список
специальных требований работодателя к письму. Программа сама собирает письмо
с фиксированными приветствием, предложением об основном стеке и заключением;
проверяет указанные навыки по резюме, обязательные ответы и дословные кодовые фразы.
Если данных для обязательного ответа
нет или требуемые начало/заключение противоречат выбранному формату,
отклик пропускается с объяснением в журнале. Факты и навыки не должны выдумываться.
По умолчанию подходят вакансии с оценкой от 70 и без критичных несоответствий.
Сам по себе более низкий уровень вакансии не является причиной отказа.

Настройки в `config.json` перечитываются в начале каждого цикла:

- `cycle_hours: 4` — длина цикла лимитов вакансий. Таймеры поднятия резюме работают отдельно.
- `max_vacancies: 400`, `max_applications: 400` — общие пределы за цикл для всех
  поисковых запросов вместе. Смена запроса не обнуляет лимиты или темп обработки.
- `minimum_score: 70` — порог соответствия.
- `max_search_pages: 100` — предел просмотра выдачи для поиска новых кандидатов.
- `review_again_after_hours: 24` — повторная оценка ранее отклонённых вакансий.
  При изменении резюме, формата письма, модели или порога они оцениваются заново.
  Значение 0 отключает этот срок ожидания.
- `delay_seconds: 3` — минимальная дополнительная пауза после обработки вакансии.
- `search_mode: "model"` — модель составляет запрос по основному резюме и определяет
  верхнюю границу опыта. План сохраняется в `output/search-plan.json` и выводится в консоль.
  Один запрос — короткая фраза из 1–4 слов, например `python backend`, `python fastapi`
  или `python junior backend`. Каждый вариант обрабатывается отдельным поиском.
  OR, AND, NOT, скобки и списки технологий в одном запросе отклоняются до поиска.
- `include_lower_levels: true` — включать опыт своего диапазона и все диапазоны ниже,
  например 3–6 лет, 1–3 года и без опыта. Порог соответствия для отклика остаётся 70.
- `empty_search_delay_seconds: 60` — пауза перед следующим запросом, если поиск
  не нашёл новых вакансий или модель повторила недавний запрос. Это предотвращает
  быстрый расход API-бюджета на пустых поисках. Команды паузы работают и во время ожидания.
- `search_query: "python backend"` — ручной запрос, используется при `search_mode: "manual"`.
- `search_location: "moscow_any"` — Москва, любой формат работы; режим по умолчанию.
  Для всей России с удалённой работой укажите `"russia_remote"`.
- `search_filters` — дополнительные параметры поиска hh.ru.

Пример переключения географии в `config.json`:

```json
"search_location": "russia_remote"
```

Поиск открывается по адресу `/search/vacancy` с запросом `text`, выбранным моделью
`search_field` (обычно `name`), диапазонами опыта `experience` и сортировкой
`order_by=publication_time`. Модель подбирает запрос и диапазон опыта; браузер
собирает вакансии непосредственно на hh.ru, платный инструмент web search не используется.
Для своего опыта и уровней ниже используются отдельные поисковые URL с одним
диапазоном каждый. Их страницы чередуются, вакансии объединяются без дублей;
`max_vacancies` и `max_search_pages` действуют на весь сбор вместе.
География остаётся выбором пользователя. В режиме `moscow_any` добавляется `area=1`,
в режиме `russia_remote` — `area=113&work_format=REMOTE`.
Параметры географии и формата задаёт выбранный режим; одноимённые параметры
из `search_filters` его не переопределяют. Подбор «Подходящие вакансии» не используется.
Точный адрес поиска выводится в консоль. Сначала собираются ссылки со страниц
выдачи, затем каждая вакансия открывается и оценивается моделью по основному резюме.
Один проход ограничен `max_search_pages` и оставшимся лимитом вакансий цикла;
после обработки собранной пачки начинается следующий запрос. Размер страницы
фиксирован: 20 вакансий. При более крупных страницах hh.ru
подгружает часть карточек отдельно; небольшой размер позволяет собрать всю выдачу.

Сообщения hh.ru «Ничего не нашлось» и «ничего не найдено», включая неразрывные
пробелы, распознаются как пустая выдача. Программа переходит к следующему диапазону
опыта или поисковому запросу. Если нет ни карточек, ни сообщения о пустом поиске,
страница не считается пустой автоматически: сохраняется `output/search-error.json`
с адресом, заголовками страницы и числом ссылок на вакансии.
Пробелы в поисковой фразе стандартно отображаются в URL знаком `+`.

В сообщении о странице «в очереди всего» — накопленный размер очереди, а «по локальной
истории пропущено всего» — накопленное число пропусков по `state.sqlite3` за текущий
сбор. При первом запуске история пустая. Полная история откликов с hh.ru не загружается:
уже отправленный отклик дополнительно проверяется на странице самой вакансии.
Сообщение «Оцениваю вакансию и готовлю письмо» означает запрос к OpenAI или чтение его кэша;
подтверждённую отправку обозначает только «Отправил отклик».

Отклик открывается нажатием кнопки на сайте. Для обычной формы программа выбирает
резюме и заполняет письмо. Если hh.ru запускает быстрый отклик без формы, программа
добавляет подготовленное письмо в его запрос до отправки. В обоих случаях перед
передачей проверяются идентификаторы вакансии и резюме, а также точный текст письма.
В консоли появляется «Запрос отклика проверен: письмо включено». Пустое или другое
письмо, другое резюме и неизвестный способ отправки блокируются.

Уже отправленные отклики остаются без изменений: программа не добавляет к ним
письма задним числом. Если сайт после новой отправки не подтверждает наличие письма,
рассылка останавливается. Подготовленный текст остаётся в `output/letters/`.

Начало проверок распределяется по четырём часам: при 400 вакансиях ориентир —
одна каждые 36 секунд, с учётом времени обработки. Если модель или сайт работают
медленнее либо новых вакансий меньше, будет обработано меньше 400. Новая отправка
после границы цикла не начинается; уже начатая операция получает подтверждение
и записывается в журнал. Платные функции и ограничения сайта не обходятся.

## Быстрый запуск на этом компьютере

Окружение `.venv` и Playwright уже подготовлены. Откройте `start.cmd`:
после входа и Enter программа продолжит постоянную работу в том же видимом окне.
Подготовка ниже нужна при установке проекта на новый компьютер.

```powershell
# Уже есть сохранённая сессия: работа в видимом браузере
.\.venv\Scripts\python.exe main.py run

# Только поднять резюме один раз
.\.venv\Scripts\python.exe main.py run --task bump --once

# Один раз собрать вакансии общего поиска
.\.venv\Scripts\python.exe main.py run --task search --once

# Один пробный проход: подготовить письма без отправки
.\.venv\Scripts\python.exe main.py run --task apply --dry-run --once
```

`--dry-run` отключает поднятие, добавление в избранное и отправку.
Он оставляет журнал и подготовленные письма, не помечая вакансии как отправленные.
Для короткого пробного прохода можно временно уменьшить `max_vacancies`.

## Пауза и продолжение

В том же терминале введите команду и нажмите Enter:

```text
INeedSomeSleep
WhyYouSoUgly
```

Первая команда ставит работу на паузу, вторая продолжает её. Регистр важен.
Команды принимаются и во время ожидания, и во время запроса к Ollama.
Начатый запрос или отправка могут закончиться; следующие действия не начинаются,
пока не будет введена команда продолжения. В паузе резюме не поднимаются.

Четырёхчасовой таймер идёт по реальному времени. Если цикл закончился во время
паузы, после продолжения начнётся новый цикл с поднятием доступных резюме.
`Ctrl+C` полностью завершает программу. Пока она нужна, оставляйте компьютер
включённым, терминал открытым и не переводите систему в сон.

В консоль выводятся открытые вакансии, оценки и причины, состояние откликов,
полные отправленные письма, добавление анкет в избранное и поднятые резюме.
Цвет результата помогает отличать состояния:

- Оранжевый — вакансия не подходит или не хватает данных для обязательного письма.
- Зелёный — отклик с сопроводительным письмом подтверждён сайтом.
- Жёлтый — подходящая вакансия с анкетой успешно добавлена в избранное.
- Красный — ошибка страницы, модели, отправки или другая проблема.

Оценка и подготовка письма ещё не окрашиваются зелёным. При перенаправлении
вывода в файл цвета отключаются; `events.jsonl` всегда содержит обычный JSON.
Например:

```text
Открыл вакансию: Python Backend-разработчик — https://hh.ru/vacancy/...
Оценил вакансию: Python Backend-разработчик | Оценка: 85/100 | Совпадает стек API и PostgreSQL
Отправил отклик: Python Backend-разработчик | Оценка: 85/100
Сопроводительное письмо:
Здравствуйте!
...
Буду рад обсудить детали.
Резюме Python Backend-Разработчик поднято
```

Результаты сохраняются в `output/`:

- `events.jsonl` — события со временем UTC, ссылками, оценками, причинами и отправленными письмами.
- `resumes.json` — список резюме; `vacancies.json` — найденные вакансии.
- `letters/<id>.txt` — подготовленные сопроводительные письма.
- `state.sqlite3` — состояние отправок, отложенные анкеты и история оценок.

Перед отправкой в базе фиксируется `submission_pending`. Если подтверждение
сайта потерялось, запись становится `submission_unknown` и автоматически
не отправляется повторно. Остальные вакансии продолжают обрабатываться.
Проверьте такую вакансию вручную в откликах hh.ru.
Не удаляйте `state.sqlite3`, если хотите сохранять историю между запусками.
Уже отправленные отклики дополнительно определяются по странице вакансии.

Режим `search` только сохраняет ссылки. Анкеты определяются при открытии формы
в режиме `apply`; незнакомые формы отклика пропускаются с записью в журнал.
Изменения вёрстки hh.ru могут потребовать обновления селекторов в `actions.py`.

## Запуск в Windows

Нужны Python 3.10+ и Microsoft Edge. В PowerShell из этой папки:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

1. При первом запуске вставьте API-ключ в скрытый ввод терминала.
2. Войдите в профиль **соискателя** в открывшемся окне hh.ru.
3. Оставьте браузер открытым и нажмите Enter в терминале.
4. Программа проверит вход и продолжит работу в том же видимом окне.

Если вы вошли раньше и сессия ещё действует, достаточно:

```powershell
.\.venv\Scripts\python.exe main.py run
```

Только вход / обновление сессии:

```powershell
.\.venv\Scripts\python.exe main.py login
```

Если `py` сообщает, что Python не установлен, установите Python 3.10+ или
используйте полный путь к имеющемуся `python.exe` вместо `py -3`.

## Другой браузер

Для Chromium сначала скачайте браузер Playwright:

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe main.py --browser chromium
```

Используйте одинаковые `--browser` и `--profile` при входе и дальнейшей работе.

## Сессия и остановка

- В Windows профиль по умолчанию: `%LOCALAPPDATA%\hh-browser\msedge\profile`.
  Он находится вне исходников и OneDrive. Для других браузеров имя папки меняется.
- Пароль и SMS-код вводятся непосредственно на сайте. Программа их не запрашивает.
  Профиль содержит данные активной сессии: не публикуйте и не передавайте его.
- Можно задать собственную папку: `--profile C:\hh-browser-profile`.
  Используйте отдельный профиль программы, а не профиль повседневного браузера.
- Один профиль может использоваться только одним запуском за раз.
- `Ctrl+C` останавливает программу и закрывает её браузер.
- При истечении сессии команда `run` завершается с кодом 2. Выполните `login`.
- При текстовой CAPTCHA программа отправляет изображение боту Telegram.
  Ответьте символами с картинки **одним сообщением**. Регистр сохраняется;
  Enter в консоли не нужен. Браузер, вкладка, форма и `sessionStorage` не
  пересоздаются. Ответ вводится в ту же форму, после чего проверяется результат.
- CAPTCHA можно пройти вручную в видимом окне браузера. После исчезновения
  проверки ожидание ответа в Telegram прекращается, программа продолжает работу.
- Неверный ответ или изменившаяся картинка приводят к новому запросу в Telegram.
  Старый ответ не применяется к новой картинке. Снимок всей страницы не отправляется.
- Перед отправкой проверяется загрузка и декодирование изображения. Если вместо
  CAPTCHA сайт показывает значок повреждённой картинки, программа ждёт загрузки
  и пробует обновить только изображение, сохраняя страницу и форму. Повреждённый
  снимок в Telegram не отправляется; бот сообщает о проблеме текстом.
- Если CAPTCHA возникла при отклике, повтор разрешается только после явного
  отказа сервера. Нужное резюме и подготовленное письмо проверяются перед передачей;
  неопределённый или уже успешный отклик повторно не отправляется.
- Команды паузы продолжают работать. Ожидание Telegram не сбрасывает таймер цикла;
  уже начатое действие может завершиться после ответа человека, а новые вакансии
  после границы текущего цикла не начинают обрабатываться.
- При недоступности Telegram программа сохраняет браузер и страницу, ожидает
  восстановления связи. Неподдерживаемая интерактивная CAPTCHA (например, выбор
  картинок вместо текста) также оставляет работу на паузе, с объяснением в журнале.
- HTTP 403/429 без признаков CAPTCHA останавливает работу с кодом 3:
  ограничение доступа или частоты может потребовать ожидания.
  Окно не открывается для одного лишь ограничения частоты запросов.
- После перезапуска сохраняются cookies и данные постоянного профиля.
  Состояние открытых вкладок и `sessionStorage` не гарантируется.

## Telegram для CAPTCHA

Настройки находятся в `config.json`, блок `telegram`. Токен хранится отдельно
в `.telegram-bot-token`; этот файл исключён из Git. `.telegram-state.json` хранит
числовые идентификаторы разрешённого пользователя и личного чата, а также позицию
чтения сообщений. Сообщения других пользователей, групп, прошлых CAPTCHA и команды
вместо ответа не используются. Ответы и токен не печатаются в журнал.

Для первого подключения откройте своего бота в Telegram и отправьте `/start`, затем:

```powershell
.\.venv\Scripts\python.exe tools/setup_telegram.py
```

Для этого компьютера личный чат `@ugly_xddd` уже привязан к боту
[@UglyCaptchaAccept_bot](https://t.me/UglyCaptchaAccept_bot). Проверка Telegram на
учебной картинке без обращения к hh.ru:

```powershell
.\.venv\Scripts\python.exe tools/test_telegram_captcha.py
```

Интеграция использует [официальный Telegram Bot API](https://core.telegram.org/bots/api).

Проверка входа использует личную страницу `/applicant/profile/me` и признаки меню
соискателя. Если hh.ru изменит вёрстку, обновите `SIGNED_IN_SELECTOR` в `main.py`.
Разметка профиля, поиска, основного резюме и формы отклика сверена на hh.ru.
Сохранение входа и отправки проверяются автоматически на локальном сайте.
Вход в отдельный профиль программы выполняется человеком. Обычный запуск
теперь включает отправку подходящих откликов; `--dry-run` позволяет проверить
работу и письма без отправки и других изменений на сайте.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Интеграционные проверки запускают Edge без окна и локальный HTTP-сервер.
Они проверяют сохранение сессии, лимит 400, переход к следующим вакансиям,
паузы и смену циклов, оценки, формат писем, анкеты, отправки и защиту от дублей.
Также проверяются цвета вывода и передача CAPTCHA через Telegram: сохранение
исходного браузера/вкладки, ввод ответа, неверный и устаревший код, защита личного
чата и токена, продолжение отклика с письмом без повторного успешного отклика.
CAPTCHA имитируется только на локальном сайте; тесты не решают реальные проверки.
Учётная запись hh.ru для них не нужна. Четырёхчасовые границы проверяются
с управляемыми часами без реального четырёхчасового ожидания.
